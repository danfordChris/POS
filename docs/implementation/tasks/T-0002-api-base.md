## Objective

The API connects to PostgreSQL via Prisma, runs migrations, exposes `/v1` with the standard error filter and generated OpenAPI, and serves a real `GET /health`.

## Scope Boundary

**In scope:**
- Prisma setup; initial migration with `user` and `operator` tables only.
- Global exception filter producing `{ error: { code, message, details } }`.
- Global validation pipe; config module reading `.env`.
- OpenAPI document generation to `api/openapi.json` + a script to check drift.
- `GET /v1/health` returning DB connectivity status.
- Request logging middleware with a correlation id.

**Out of scope:**
- Business/membership tables and RLS (T-0004).
- Any auth endpoints (T-0003).

## Acceptance Criteria

- [x] `prisma migrate deploy` on a fresh DB creates `user` and `operator` tables (verified against a dropped/recreated `pos_dev`).
- [x] `GET /v1/health` returns 200 `{ status:"ok", db:"up" }` when Postgres is reachable, 503 `{ status:"error", db:"down" }` when not (verified live + e2e).
- [x] A class-validator `BadRequestException` yields HTTP 400 with `error.code = "validation_error"` and a `details` array (unit test on `AllExceptionsFilter`).
- [x] `api/openapi.json` regenerated by `build`; `openapi:check` exits non-zero on drift.
- [x] `PrismaService.$connect` / `pingDatabase` / `$disconnect` are all try/catch-wrapped; a startup connection failure logs and boots anyway so health reports `db:down` (503) rather than crashing. Unknown routes return the JSON envelope, not HTML.
